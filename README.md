# 高利回り日本株 TOP30

東証上場の普通株から、**実績配当ベースの配当利回り上位30銘柄**を毎営業日更新して表示する Web アプリです。

サーバーを持たない構成です。GitHub Actions が営業日の 20:00 (JST) にデータを生成し、
GitHub Pages が静的サイトとして配信します。運用コストは 0 円で、APIキーも不要です。

---

## 構成

```
batch/          Python: 株価・配当の取得と TOP30 の算出
  data/         JPX Excel の同梱版（ダウンロード失敗時のフォールバック）
  src/          取得ロジック（screener → verifier → ranking → news）
web/            React + TypeScript + Vite のフロントエンド
  public/data/  バッチが生成する top30.json（コミット対象）
.github/        データ更新とデプロイのワークフロー
```

データの流れ:

```
JPX から銘柄一覧を自動ダウンロード ─→ 普通株 約3,700銘柄
                  ↓
            ① スクリーニング   yf.download で一括取得（約6分）
                  ↓            高利回りの候補150銘柄に絞る
            ② 検証            Ticker.info で個別に確定（約4分）
                  ↓            TOP30 が確定
            ③ ニュース         Google ニュース RSS（30銘柄・約20秒）
                  ↓
            top30.json ─→ React 静的サイト
```

### なぜ 2 段階なのか

全銘柄を `Ticker.info` で 1 件ずつ取ると 30 分以上かかり、レート制限にも頻繁に当たります。
一方 `yf.download` の一括取得は速い（100銘柄あたり約7秒）代わりに、**配当額の株式分割調整が
銘柄によって不揃い**という問題があります。

たとえば日本製鉄 (5401) は 2025-09-29 に 1:5 の株式分割をしていますが、終値は分割調整済みなのに
同日付の配当だけが分割前の単位で入っており、そのまま計算すると利回りが 10.6%（実際は 3.5%）と出ます。
これは全銘柄に一律の補正をかけて直せる類のものではなく、三菱重工 (7011) やブリヂストン (5108) では
同じ「分割日と同日の配当」が正しく調整済みでした。

そこで一括取得は**候補を絞るためのふるい**と割り切り、上位候補だけ Yahoo が銘柄単位で公開している
`trailingAnnualDividendRate`（分割調整済み）で数値を確定させています。

## ローカルで動かす

```bash
make setup       # Python 仮想環境と npm 依存関係（初回のみ）
make data-quick  # 先頭300銘柄で動作確認（1分程度）
make dev         # http://localhost:5173
```

全銘柄で生成する場合は `make data`（10分程度）を使います。

| コマンド | 内容 |
| --- | --- |
| `make setup` | 初回セットアップ |
| `make data` | 全銘柄を取得して `web/public/data/top30.json` を生成 |
| `make data-quick` | 先頭300銘柄だけで生成（動作確認用） |
| `make dev` | 開発サーバー |
| `make preview` | 本番ビルドをローカルで配信 |

## 利回りの定義

```
配当利回り(%) = 年間配当（実績・直近12か月） ÷ 終値 × 100
```

- 予想配当ではなく**実績ベース**です。
- 実績が取得できない銘柄のみ、直近1期の年間配当で代替します（画面とCSVに根拠を表示）。
- 対象は東証上場の**普通株のみ**。ETF・ETN・REIT・インフラファンド・優先株・外国株・PRO Market は除外します。
- 実績配当が会社予想の 1.5 倍を超える銘柄には「**特別配当の疑い**」を表示します。記念配当などで
  一時的に利回りが跳ね上がっている可能性があるためです。画面のチェックボックスで除外もできます。

### 証券コードの扱い

JPX は 2024 年以降の新規上場に `130A` のような**英数字コード**を割り当てています。
数字4桁に限定すると実在の上場企業を 140 社以上取りこぼすため、4文字の英数字を対象としています。
優先株・種類株はコードが5桁（例: `25935` 伊藤園第1種優先株式）なので、この条件で自動的に除外されます。

## 銘柄マスタ

銘柄一覧は実行のたびに [JPX 公式](https://www.jpx.co.jp/markets/statistics-equities/misc/01.html) から
自動でダウンロードします。手作業は不要です。

取得したファイルは `batch/.cache/` に置かれ、リポジトリにはコミットしません（830KB のバイナリを
毎日コミットするとリポジトリが肥大化するため）。

JPX 側の URL 変更やメンテナンスでダウンロードできない場合は、以下の順に代替します。

1. 前回ダウンロードしたキャッシュ
2. リポジトリ同梱の `batch/data/data_j.xls`

同梱ファイルは最後の保険なので、内容が古くてもバッチは止まりません。ただし上場廃止銘柄が
取得エラーとして積み上がるため、フォールバックが続く場合は同梱ファイルを差し替えてください。

ネットワークを使わずに動かしたいときは `--no-download` を付けます。

```bash
cd batch && ../.venv/bin/python -m src.build --no-download
```

## 自動更新

`.github/workflows/update-and-deploy.yml` が以下のタイミングで動きます。

| 起動 | データ取得 | デプロイ |
| --- | --- | --- |
| 平日 20:00 JST（cron） | あり（祝日はスキップ） | あり |
| Actions からの手動実行 | あり（祝日でも実行） | あり |
| `main` への push | なし | あり |

土日祝・年末年始は取得をスキップします。同一営業日のうちは終値が変わらないため、
1日1回で十分です。

生成された `top30.json` はリポジトリにコミットされるので、過去のランキングは Git 履歴から辿れます。

### 初回のセットアップ

リポジトリの **Settings → Pages → Build and deployment → Source** を `GitHub Actions` に変更してください。
これを設定しないとデプロイジョブが失敗します。

## 画面の使い方

ダッシュボードと一覧表は、検索・絞り込みバーのすぐ下にあるタブで切り替えます。

**銘柄をタップすると、その企業の詳細ポップアップ**が開きます。ダッシュボードのカード、一覧表の行の
どちらからでも開けます。配当・株価の内訳、業績関連ニュース、時価総額・従業員数・本社・公式サイト、
事業内容を表示します。Escape キーか背景のタップで閉じます。

### 業績関連ニュース

各銘柄について、決算に関する見出しを最大3件表示します。取得元は **Google ニュースの RSS** です。
見出しをタップすると配信元の記事が新しいタブで開きます。

情報源の選定は実測で決めました。yfinance にも `Ticker.news` がありますが、青山商事は 0 件、
KDDI は 10 件あるものの Coincheck や BMW の記事で本人と無関係、しかもすべて英語で使えませんでした。
Google ニュース RSS は TOP30 の全銘柄で 11〜62 件がヒットし、日本語の決算記事が並びます。

**この RSS は Google が公式に文書化した API ではありません。** 予告なく仕様変更や遮断が起きうるため、
ニュースの取得失敗はバッチを止めず、空のまま先に進みます（画面には「取得できませんでした」と出ます）。
取得は 1 日 1 回・TOP30 の 30 銘柄だけです。

見出しの選定は Google の検索結果順なので、まれに関連の薄い記事が混ざります。その旨は画面にも
注記しています。

**事業内容は英語です。** Yahoo Finance の `longBusinessSummary` をそのまま載せています。日本語の事業概要を
返すソースが yfinance にないため、翻訳せず原文のまま出し、画面上にも「英語原文」と明記しています。

### 日本語に翻訳する

事業内容の見出しに **「日本語に翻訳」ボタン**があります。ブラウザ内蔵の翻訳機能
（[Translator API](https://developer.chrome.com/docs/ai/translator-api)）を使うため、APIキーも通信費も
かかりません。翻訳は端末内で完結し、本文がどこかへ送信されることもありません。押すと訳文に切り替わり、
「原文を表示」で戻せます。訳文には「機械翻訳」と表示します。

**このボタンは Chrome 138 以降のデスクトップでのみ表示されます。** モバイル版 Chrome・Safari・Firefox は
Translator API に対応しておらず、その場合ボタンは出ません（押せないボタンを見せても仕方がないため）。
初回だけ翻訳モデルのダウンロードが走るので、進捗をボタン上に表示します。

なお「このページを翻訳」というブラウザ標準の機能は、ページ側から呼び出す手段が提供されていません。
そちらを使いたい場合は、ブラウザのメニューから起動してください。

## 制約と既知の問題

- **データ遅延・欠損を許容する設計**です。取得できなかった銘柄はスキップし、取得できた分でランキングを構成します。
  取得できなかった件数は画面下部に表示されます。
- yfinance は非公式APIのため、レート制限に当たることがあります。取得できなかった銘柄は時間を置いて
  最大3ラウンドまで取り直しますが、それでも数十銘柄は落ちます（多くは上場廃止銘柄）。
- GitHub Actions の IP は共有のため、ローカル実行より制限が厳しく出る可能性があります。
- 株価は**終値（前営業日終値）**です。リアルタイム気配は扱いません。
- 詳細ポップアップの企業情報（事業内容・従業員数・本社・公式サイト）は Yahoo Finance 由来で、
  銘柄によっては取得できません。その場合は「—」または取得できなかった旨を表示します。
- `data/top30.json` は URL が毎回同じで、GitHub Pages が `max-age=600` を返します。そのため
  ブラウザは初回読み込みでも必ずサーバーに問い合わせる（`cache: 'no-cache'`）ようにしています。
  これを省くと、新しい JS が古いデータを描画して項目が欠けて見えます。

## 元の仕様書からの変更点

旧プロジェクト（`high-yield-stocks`）の仕様書をもとにしていますが、サーバーレス構成にしたことで
いくつか変わっています。

| 項目 | 仕様書 | 本実装 | 理由 |
| --- | --- | --- | --- |
| 銘柄マスタ更新画面 | Excel をアップロードして DB を UPSERT | **廃止** | JPX から自動ダウンロードするため画面自体が不要になった |
| 手動更新ボタン | 取得ジョブを非同期で起動 | 公開済みデータの再取得のみ | サーバーがないためジョブを起動できない。必要なときは Actions から手動実行する |
| 証券コード | 数字4桁のみ | 4文字の英数字 | JPX が 2024 年以降 `130A` 形式を使用しており、数字限定だと 144 社を取りこぼす |
| データ取得 | 全銘柄を `Ticker.info` で 0.5 秒間隔（約30分） | 一括取得＋候補のみ個別取得（約10分） | レート制限を避けつつ短時間で完了させるため |
| 利回り強調色 | `#48bb78` | 文字は `#276749`、塗りは `#48bb78` | 白背景に `#48bb78` の文字はコントラスト比 2.43 で WCAG AA(4.5) に届かない |
| 銘柄詳細ページ / About ページ | MVP 後の予定 | 未実装 | 仕様書でも MVP 対象外 |
